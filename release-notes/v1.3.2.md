Yummle v1.3.2 is a small frontend-only release that hands the sidebar Explore section to you: the four hardcoded shortcuts (`Music`, `Gaming`, `Podcasts`, `Education`) become a personal list of search links that you manage from the menu itself. No backend changes — Explore links stay client-side shortcuts to the archive's search.

## Added

- **Add a link from a pop-up.** A "+" control next to the Explore heading opens a small dialog with one text field: type a query, press Enter (or Add), and the query becomes a new Explore link. Its label and its search are the same text, and clicking it runs the same search as typing the query in the topbar. Escape or a click outside cancels.
- **Edit links in place.** Hovering (or focusing) a link reveals a pencil control that opens the same pop-up prefilled; saving rewrites the link where it sits — label, icon letter, and destination — without changing its position in the list.
- **Remove anything.** A per-link × control deletes user-added and default links alike. When the list is empty the section shows a hint ("Search the archive and pin a query here.") and the "+" control still works for starting over.
- **Sensible guards.** Adding a query that already exists — case-insensitively — is a no-op with an "already saved" status instead of a duplicate row, and empty or whitespace-only input is rejected.

## Changed

- **The Explore list is now a per-browser preference.** It persists in `localStorage` under `kapsel.exploreLinks` (alongside the other sticky UI choices) and survives reloads. A profile that has never touched the editor still sees the same four defaults, and clearing the key restores them.

## Notes

- **The editor affordances are a desktop-size feature.** Below 1180px the icon-only sidebar collapse keeps the plain links exactly as before, and below 780px the section stays hidden; the pop-up and the add/edit/remove controls only appear at desktop sizes.
- **Dialog state is announced.** The "+" and every per-link edit control carry `aria-haspopup="dialog"`, a mode-aware `aria-expanded`, and `aria-controls`, so assistive tech hears which control opened the editor and when it closes.

No upgrade steps: nothing to migrate and nothing to configure, and an archive whose household never uses the editor behaves exactly as before.
