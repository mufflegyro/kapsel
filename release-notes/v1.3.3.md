Yummle v1.3.3 is a small reliability release with two behind-the-scenes fixes: a lost live-job update that could leave the watch page (and the flaky smoke test that kept catching it) missing the transition to a finished download, and a timestamp ordering hazard that could make background jobs and media retention compare times in the wrong order when their timestamps landed inside the same second. No feature changes and no data migrations.

## Fixed

- **Live download updates survive a racing snapshot.** Starting a download from the watch page now re-checks the live jobs feed when the server accepts the job. Previously, a live snapshot that arrived in the window between clicking download and the server's response was silently discarded (the app hadn't yet linked the job to the video), so the page could stay on "Downloading" even after the job finished — most visible on slow connections, and the cause of the recurring flaky smoke test.
- **Timestamp comparisons no longer misorder sub-second times.** Timestamps are stored as text, and RFC 3339's habit of stripping trailing zeros made two times inside the same second compare in the wrong order (for example `…00.1Z` sorted after `…00.100000001Z`). A new comparison rule now orders timestamp text by actual time everywhere it matters: job claiming and stale-job recovery, and media retention cutoffs (the watched-grace and stale-auto rules). Text that isn't a timestamp keeps its previous ordering.

## Notes

- **No data is rewritten.** The timestamp fix normalizes at comparison time; existing rows, API responses, and displayed timestamps are unchanged.
- **The job race fix is in the app, not the test.** The flaky "catalog download success refreshes route data once" browser test now passes reliably (its documented failure reproduced 4/4 on a clean tree); the fix makes both orderings of "snapshot vs. accepted job" correct for real servers too.
- **Slightly more CPU when claiming jobs.** Job claiming now compares timestamps by parsing them; at household archive sizes this is unmeasurable, and job rows are transient.

No upgrade steps: nothing to migrate, nothing to configure, and behavior only changes where the old ordering was wrong.
