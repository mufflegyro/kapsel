Yummle v1.3.4 ships one new operator-facing setting and two structural cleanups with no visible behavior change: manual downloads can now be opted into the stale-media retention rule, the background scheduler's job-ownership boundaries are written down in one place, and the download worker's monolithic source file is split into focused files. No data migrations.

## Added

- **Opt-in retention for manually downloaded media.** The stale-cleanup rule (unstarted, unwatched media beyond the newest 2 per channel, removed after 14 days) used to apply only to channel auto-downloads. Setting `KAPSEL_RETENTION_INCLUDE_MANUAL=1` opts manual downloads in: channel-bound manual downloads compete for the same newest-2-per-channel slots as auto-downloads, and channel-less manual downloads (direct URL downloads) become eligible once unstarted and past the cutoff. Imports are never removed by the stale rule, started videos are never removed, and "Keep forever" still protects everything. Default behavior is unchanged — manual media stays out of retention unless you opt in.

## Changed

- **Scheduler ownership is now documented and enforced in code.** Background loops own only their cadence; scheduling policy (dedupe, throttling, failure re-arm) lives in dedicated scheduling-policy functions backed by shared job-store helpers, so the same rules apply to every scheduled job. Documented in `docs/scheduler.md`.
- **The download worker is split into focused files.** The 3,300-line `downloader.go` is now nine files grouped by responsibility (yt-dlp execution, ingestion, catalog sync, enqueueing, retention, scheduling, URL handling, job dispatch). Pure restructuring — no behavior change, all existing tests pass unchanged.

## Notes

- **The retention opt-in is operator-level.** Like the watched-cleanup setting, it is configured per instance via environment variable (`KAPSEL_RETENTION_INCLUDE_MANUAL`, default off) and documented in `docs/deployment.md` and `deploy/kapsel.env.example`; per-video opt-in can be layered later.
- **Internal file split, no API changes.** The download worker split moves code without changing any behavior, API, or storage format.

No upgrade steps: nothing to migrate, and nothing changes unless you set `KAPSEL_RETENTION_INCLUDE_MANUAL=1`.
