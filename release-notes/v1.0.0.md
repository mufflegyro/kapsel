First tagged release of Yummle — the opinionated fork of Kapsel, a small self-hosted video archive for one person or household — and the first release the new self-update flow can install.

Yummle is a collection of tweaks and quality-of-life improvements for adding media from different sources and connecting to additional front ends, with Docker as the main deployment addition. The Kapsel naming is deliberately kept for the binary, configuration, and release assets, since that is what is running the show underneath.

## Highlights

### Self-update from GitHub releases (new)

Yummle can now keep itself current, with the archive admin firmly in control:

- A scheduled job checks this repository for a newer release once a day by default (`KAPSEL_UPDATE_CHECK_INTERVAL`, set `0s` to disable; `KAPSEL_UPDATE_REPO` overrides the repository). A **Check Now** button in Settings triggers the same check on demand.
- A newer release appears as a pending offer under **Settings → Updates**. Nothing is installed until it is explicitly approved there.
- On approval Yummle downloads the artifact for its platform, verifies it against the release's SHA-256 checksums, takes a database backup, atomically replaces the binary (keeping the previous one as a rollback copy), and restarts gracefully.
- Failure-safe by design: failed checks back off exponentially, corrupted downloads or failing backups abort before the binary is touched, and interrupted updates can be re-approved and retried. The running archive is never left broken.

### Also in this release

- Browser playback with seeking, captions, and preview thumbnails.
- Channel and playlist management, including `.csv` import.
- Full-text search over local metadata (titles, descriptions, subtitles, comments) via SQLite FTS.
- Automatic yt-dlp updates to the latest nightly.
- SQLite metadata backup and restore, separate from large media files.
- Docker deployment with `.env`-based configuration.

## Install

1. Download the binary for your platform from the assets below (`kapsel_linux_amd64`, `kapsel_linux_arm64`, `kapsel_darwin_amd64`, `kapsel_darwin_arm64` — the Kapsel naming carries through to the release assets) plus `checksums.txt`.
2. Verify the SHA-256 digest of your download against `checksums.txt`. All binaries are statically linked with the web UI embedded — no runtime dependencies.
3. Make the binary executable and point it at a writable data directory. See [docs/deployment.md](https://github.com/mufflegyro/yummle/blob/main/docs/deployment.md) for the full setup, systemd and Docker instructions.

Docker users: build with `docker compose up -d --build` or deploy with `scripts/deploy.sh <host>`. Containers update by pulling a rebuilt image — in-app update checks are disabled by default there.

## Notes

- Update checks use the unauthenticated GitHub API (60 requests/hour per IP) and back off automatically when rate-limited.
- Self-update needs a writable binary path; it is refused on `dev` builds and, by default, inside containers.
